# Diktant — генератор аудио-диктантов

Превращает текстовый файл в аудиодиктант с заданным темпом (слов в минуту):
текст разбивается на смысловые отрезки, каждый озвучивается синтезом речи,
между отрезками вставляются паузы такой длины, чтобы весь диктант уложился
ровно в целевой темп.

Зависимостей нет — только стандартная библиотека Python 3.10+.

## Что такое WPM здесь

`--wpm` — это **общий темп диктанта** (все слова / вся длительность аудио),
а не скорость речи диктора. Диктор читает в естественном темпе (`--speed`),
а нужный WPM набирается паузами — как на настоящем диктанте, когда учитель
ждёт, пока класс допишет.

Ориентиры для письма от руки (в русском тексте ≈ 7 знаков на слово с
пробелами и знаками препинания, поэтому нормы «в знаках» делим на 7):

| Кто пишет | Темп письма | `--wpm` |
|---|---|---|
| 2 класс | 20–30 знаков/мин | 3–4 |
| 3–4 класс | 35–50 знаков/мин | 5–7 |
| 5–9 класс | — | 8–15 |
| старшие классы, взрослые | — | 15–25 |

Это предел скорости переписывания; на диктанте с осмыслением и проверкой
написанного разумно брать нижнюю границу. Стенография быстрее: её цель —
поспевать за живой речью (≈ 100–150 сл/мин), и темп поднимают постепенно.

Вместо `--wpm` можно задать желаемую длительность всего диктанта напрямую —
`--duration`, темп посчитается автоматически из числа слов в тексте:

```powershell
python diktant.py text.txt --duration 4m        # 4 минуты
python diktant.py text.txt --duration 4:30      # 4 мин 30 с
python diktant.py text.txt --duration 270s      # 270 секунд
```

Пауза после отрезка пропорциональна числу слов в нём, плюс добавка на знак
препинания: в конце предложения — `--sentence-extra` (длиннее, на точку/
вопрос/восклицание), после запятой, тире или двоеточия внутри предложения —
`--clause-extra` (короче, просто на вдох).

### Рекап — фраза целиком перед надиктовкой

Классика диктанта: сначала учитель читает предложение целиком (чтобы был
понятен смысл), потом — по частям, с паузами на запись. Скрипт делает так
же (`--recap`, включено по умолчанию): перед первым отрезком каждого
предложения, разбитого на несколько частей, сначала звучит фраза целиком,
короткая пауза — и только потом обычная надиктовка по кусочкам. Время на
рекап учитывается в общем бюджете темпа наравне с остальной речью, так что
`--wpm` по-прежнему выдерживается точно. Предложения, прочитанные одним
неразрезанным отрезком (короткие, без запятых), не дублируются — рекап там
был бы дословным повтором того же самого. Отключить — `--no-recap`.

## Заголовок и шапка текста

В начале каждого файла диктор читает заголовок — название текста, автора,
число слов в диктанте и темп: «Упражнение 100. Диктант из 143 слов. Темп 20
слов в минуту.» (с `--duration` —
«Длительность 4 минуты 30 секунд.»). Заголовок звучит один раз (без
`--repeat`) и в расчёт темпа не входит: `--wpm` выдерживается по самому
диктанту, как и при `--full-read`.

Название и автора можно задать необязательной шапкой в начале `.txt`:

```
---
Название: Пушкин — великий художник слова
Автор: по В. Г. Белинскому
---
Пушкин — великий художник слова. …
```

Ключи — `Название`/`title`, `Автор`/`author`; любые другие (`Уровень: 5 класс`)
попадают в комментарий mp3. Шапка не озвучивается как текст и не считается в
словах. Без шапки название берётся из имени файла: `Exercise-100` →
«Упражнение 100».

## Несколько темпов сразу

```powershell
python diktant.py examples/Exercise-100.txt --wpm 15,20,25
# -> Exercise-100-15-wpm.mp3, Exercise-100-20-wpm.mp3, Exercise-100-25-wpm.mp3
```

Синтез отрезков от темпа не зависит, поэтому выполняется один раз; для
каждого значения пересчитываются только паузы (и озвучивается свой
заголовок). С несколькими значениями `-o` не указывается — имена выводятся
автоматически.

## Теги mp3

В `.mp3` записываются ID3-теги: `title` — «название — 20 сл/мин», `album` —
название (варианты одного текста группируются в плеере), `artist` — автор из
шапки, `genre` — «Диктант», `comment` — фактический темп, число слов,
длительность, голос и прочие ключи шапки. В `.wav` теги не пишутся.

## Быстрый старт

```powershell
# Посмотреть разбивку и тайминг, ничего не синтезируя
python diktant.py "examples/Exercise-86.txt" --dry-run --wpm 20

# Офлайн-синтез голосом Windows (без ключей, качество — какое есть)
python diktant.py examples/Exercise-86.txt --backend sapi --wpm 20

# Yandex SpeechKit — хорошее качество русской речи
$env:YANDEX_API_KEY = "AQVN..."
python diktant.py examples/Exercise-86.txt --wpm 20 --voice alena
# -> examples/Exercise-86-20-wpm.mp3
```

## Движки синтеза

| Движок | Ключ | Качество | Примечание |
|---|---|---|---|
| `yandex` (по умолчанию) | `--api-key` или `YANDEX_API_KEY` | высокое | Yandex SpeechKit v1, формат LPCM |
| `sapi` | не нужен | зависит от установленных голосов | System.Speech, только Windows, офлайн |

Голоса: `python diktant.py --list-voices --backend sapi` (или `--backend yandex`
для списка русских голосов SpeechKit).

Ключ Yandex — это Api-Key сервисного аккаунта с ролью `ai.speechkit-tts.user`
(Yandex Cloud → Сервисные аккаунты → Создать API-ключ).

## Основные параметры

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-o` / `--output` | имя из входного файла | выходной файл `.wav` или `.mp3` |
| `--format` | `mp3` | расширение автоимени, когда `-o` не задан |
| `--mp3-bitrate` | `128k` | битрейт при записи в `.mp3` |
| `--wpm` | 20 | целевой темп диктанта, слов в минуту; список через запятую (`15,20,25`) — по файлу на значение |
| `--duration` | — | вместо `--wpm`: уложить весь диктант в заданное время (4, 4m, 4:30, 270s) |
| `--speed` | 1.0 | скорость речи диктора (0.5–2.0) |
| `--max-words` / `--min-words` | 5 / 2 | границы длины отрезка для чтения |
| `--repeat` | 1 | сколько раз читать каждый отрезок |
| `--repeat-gap` | 0.8 | пауза между повторами отрезка, с |
| `--min-pause` | 1.0 | минимальная пауза после отрезка, с |
| `--sentence-extra` | 1.0 | добавка к паузе в конце предложения, с |
| `--clause-extra` | 0.4 | добавка к паузе после запятой/тире/двоеточия внутри предложения, с |
| `--recap` / `--no-recap` | вкл. | фраза целиком перед надиктовкой по частям |
| `--recap-pre-pause` | 1.5 | пауза после рекапа, перед началом надиктовки, с |
| `--full-read` | none | сплошное чтение текста `before` / `after` / `both` |
| `--full-read-pause` | 4.0 | пауза вокруг сплошного чтения, с |
| `--lead-in` / `--tail` | 1.0 / 3.0 | тишина в начале и в конце файла, с |
| `--no-trim` | — | не срезать тишину по краям синтезированных отрезков |
| `--cache-dir` | `.tts_cache` | кэш синтеза (не платить за повторные прогоны) |
| `--dry-run` | — | показать план без синтеза |
| `--script` | — | вывести подробный TTS-скрипт: текст и паузы по порядку воспроизведения |

Классический школьный сценарий — прочитать текст целиком, потом диктовать
по частям с повторами:

```powershell
python diktant.py text.txt --wpm 45 --repeat 2 --full-read before
```

## Имя выходного файла

Без `-o` файл кладётся рядом с исходным текстом, а к имени приписывается
темп или длительность: `Exercise-100.txt` → `Exercise-100-20-wpm.mp3`, а с
`--duration 4:30` → `Exercise-100-4m30s.mp3`. Расширение автоимени задаёт
`--format`. Для текста из stdin (`-`) автоимя не вывести — нужен явный `-o`.

## Формат вывода

По умолчанию `.mp3` (`--format wav` — записать `.wav`). Для `.mp3` нужен
`ffmpeg` в `PATH` (`winget install Gyan.FFmpeg`); если его нет, автоимя
получает расширение `.wav`. Явно указанный `-o ... .mp3` без ffmpeg —
ошибка.

`.wav` — 48 кГц, 16 бит, моно, пишется напрямую; расширение выходного файла
решает, в каком формате сохранять, независимо от `--format`.

## Кэш

Синтезированные отрезки складываются в `.tts_cache/` с ключом по тексту,
голосу и скорости. Подбор темпа (`--wpm`) не требует нового синтеза —
меняются только паузы, поэтому повторные прогоны бесплатны и мгновенны.
Отключить: `--cache-dir ""`.
